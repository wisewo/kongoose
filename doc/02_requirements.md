# Functional and Non-Functional Requirements

## Priority Rule

1. 과제 안내서의 요구사항은 반드시 만족해야 하는 상위 조건으로 본다.
2. 회의록은 팀이 정한 게임 콘셉트와 세부 기능으로 본다.
3. 과제 안내서와 회의록이 충돌하면 과제 안내서를 우선한다.
4. 설계 결정사항은 기능 요구사항과 비기능 요구사항에 명확히 반영한다.
5. 회의록에 있지만 첫 버전 범위와 맞지 않는 기능은 선택 기능 또는 보류 기능으로 분리한다.

## Conflict and Scope Notes

| 구분 | 내용 | 처리 |
|---|---|---|
| 결정 | 첫 버전 UI는 클릭 가능한 버튼이 아니라 키 안내 텍스트와 키보드 입력으로 동작한다. | 문서의 선택 행동은 키 입력 기준으로 쓴다. |
| 결과 화면 | 클리어 후 자동으로 다음 스테이지로 넘어가지 않는다. | 결과 화면에서 N/R/S/B/M/Esc 중 플레이어가 다음 행동을 선택한다. |
| 저장 형식 | 저장 파일은 `progress.json`이며 JSON으로 `unlocked_stages`, `best_stars`를 기록한다. | `SaveManager`와 `Progress` 책임으로 명시한다. |
| 강 칸 진입 | `TerrainMap.can_enter()`는 강 칸을 막지 않는다. | 자라가 없는 강 추락과 화면 밖 밀림은 `Stage`가 판정한다. |
| 2.5D 표현 | 게임 로직은 2D 격자 좌표를 유지하고, `StageRenderer`가 얕은 등각 투영으로 그린다. | 판정과 렌더링 책임을 분리한다. |
| 결정 | 이동 결과는 별도 Result Object 대신 문자열 상수(`MOVE_BLOCKED`, `MOVE_MOVED`, `MOVE_CLEARED`, `MOVE_FAILED`)로 전달한다. | 단순한 첫 버전 구조를 유지한다. |
| 결정 | 갱신 결과는 별도 Result Object 대신 문자열 상수(`UPDATE_SAFE`, `UPDATE_WARNING`, `UPDATE_STUDENT_CROWD_ACTIVE`, `UPDATE_TURTLE_RIDE`, `UPDATE_FAILED`)로 전달한다. | 단순한 첫 버전 구조를 유지한다. |

## Non-Functional Requirements

| ID | Requirement | Source | Priority | Related Use Case |
|---|---|---|---|---|
| NFR-01 | 게임은 Python 3.10+ 환경에서 실행 가능해야 한다. | 과제 안내서 | Must | UC-01 |
| NFR-02 | GUI 라이브러리는 Pygame으로 확정한다. | 결정사항 | Must | UC-01 |
| NFR-03 | 런타임 소스 코드는 500~1,500줄 규모 안에서 유지되어야 한다. | 과제 안내서 | Must | 전체 |
| NFR-04 | 코드는 가독성과 유지보수성을 고려하여 작성되어야 한다. | 과제 안내서 | Must | 전체 |
| NFR-05 | 게임은 키보드 입력에 대해 즉각적인 반응을 제공해야 한다. | 과제 안내서, 회의록 | Must | UC-05 |
| NFR-06 | 충돌, 추락, 클리어 판정은 플레이어 이동 직후와 게임 루프 갱신 직후에 같은 `Stage.evaluate_player_state()` 규칙으로 처리되어야 한다. | 회의록, 결정사항 | Must | UC-05, UC-06, UC-07 |
| NFR-07 | 저장 데이터는 게임 재실행 후에도 유지되어야 하며, 손상되었거나 읽을 수 없는 저장 파일은 기본 진행 상태로 복구되어야 한다. | 과제 안내서, 결정사항 | Must | UC-01, UC-05 |
| NFR-08 | 스테이지별 난이도와 데이터는 플레이 중 실시간으로 변하지 않고 고정되어야 한다. 단, 자전거 시작 column은 스테이지 초기화 시 연속 row band 단위로 무작위 offset을 적용한다. | 회의록, 결정사항 | Should | UC-05 |
| NFR-09 | 스테이지가 진행될수록 난이도가 높아지도록 장애물 종류, 배치, 강 구간, 발판 수, 학생 무리를 조합해야 한다. | 회의록, 결정사항 | Should | UC-05 |
| NFR-10 | 자전거와 강물 환경음은 스테이지별 고정 반복음으로 재생하고, 학생 무리 사운드는 학생 무리가 활성화되는 순간의 효과음으로 재생한다. | 회의록, 결정사항 | Should | UC-05 |
| NFR-11 | 게임의 이동, 충돌, 발판 탑승, 실패, 클리어 판정은 2D 격자 좌표와 `TerrainMap`의 정적 지형 정보를 기준으로 처리되어야 하며, 2.5D 시각 표현에 의해 판정 결과가 달라져서는 안 된다. | 결정사항 | Must | UC-05 |
