# 길Kon너 Goose들

길Kon너 Goose들은 건국대학교 캠퍼스를 배경으로 한 Pygame 기반 격자 이동 게임입니다. 플레이어는 `kongoose(건구스)` 캐릭터를 조작해 도로, 강, 인파, 자전거 같은 장애물을 피하고 각 스테이지의 목표 지점까지 안전하게 이동해야 합니다.

기본 아이디어는 길 건너기 게임을 모티프로 하지만, 건국대 캠퍼스 테마, 스테이지별 기믹, 사운드 효과, 진행 상황 저장, 클리어 시간 기반 별점 시스템을 추가해 차별화했습니다.

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | 길Kon너 Goose들 |
| 장르 | 2.5D 캠퍼스 길 건너기 / 아케이드 |
| 개발 언어 | Python 3.10+ |
| GUI 라이브러리 | Pygame |
| 실행 방식 | `python -m src` |
| 주요 목표 | 장애물을 피하고 스테이지를 클리어하기 |

## 2. 게임 규칙

- 메인 화면에서 게임을 시작하고 스테이지 선택 화면으로 이동합니다.
- 잠금 해제된 스테이지를 선택해 플레이할 수 있습니다.
- 플레이어는 격자 단위로 이동하며 목표 지점까지 도달해야 합니다.
- 자전거와 충돌하거나 강에 빠지는 등 위험 요소에 닿으면 해당 스테이지에 실패합니다.
- 목표 지점에 도달하면 스테이지가 클리어됩니다.
- 클리어 시간에 따라 별점이 계산되며, 진행 상황은 파일에 저장됩니다.
- 이전 스테이지를 클리어하면 다음 스테이지가 잠금 해제됩니다.

## 3. 조작 방법

| 입력 | 동작 |
|---|---|
| 방향키 | 플레이어 이동 |
| 메뉴 화면 안내 키 | 스테이지 선택, 재시작, 메인 화면 이동 등 |

게임 내 메뉴 조작은 각 화면에 표시되는 안내 문구를 기준으로 진행합니다.

## 4. 주요 기능

- Pygame 기반 GUI 윈도우 실행
- 메인 화면, 스테이지 선택 화면, 게임 진행 화면, 실패 화면, 결과 화면 전환
- 4개의 기본 스테이지와 스테이지별 장애물/기믹 구성
- 이동, 충돌, 클리어, 실패 조건 처리
- 클리어 시간 측정 및 별점 계산
- 진행 상황 저장 및 불러오기
- 배경 음악, 이동 효과음, 충돌 효과음, 환경음 등 사운드 재생
- 사용자 정의 클래스를 활용한 객체지향 구조
- `pytest`, `ruff`를 이용한 테스트 및 코드 품질 확인 가능

## 5. 설치 및 실행 방법

### 5.1 저장소 다운로드

```bash
git clone https://github.com/wisewo/kongoose.git
cd kongoose
```

### 5.2 가상환경 생성 및 활성화

Windows PowerShell 기준:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

macOS / Linux 기준:

```bash
python -m venv .venv
source .venv/bin/activate
```

### 5.3 패키지 설치

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

### 5.4 게임 실행

```bash
python -m src
```

## 6. requirements.txt 구성

현재 프로젝트 기준으로 `requirements.txt`는 다음과 같이 구성되어 있습니다.

```txt
pygame>=2.5,<3
pytest>=8,<9
ruff>=0.11,<1
```

- `pygame`: 게임 실행에 필요한 핵심 라이브러리입니다.
- `pytest`: 테스트 실행용 개발 도구입니다.
- `ruff`: 코드 스타일 및 정적 분석용 개발 도구입니다.

## 7. 프로젝트 구조

```text
kongoose/
├─ assets/                 # 이미지, 사운드 등 게임 리소스
├─ data/stages/            # 스테이지 데이터
├─ doc/                    # 프로젝트 문서
├─ src/                    # 게임 핵심 패키지
│  ├─ __main__.py          # 게임 실행 진입점
│  ├─ game.py              # Game 클래스, 메인 루프, 화면 전환 관리
│  ├─ models.py            # 플레이어, 스테이지, 장애물 등 게임 모델
│  ├─ resources.py         # 이미지/사운드 리소스 관리
│  ├─ stage_catalog.py     # 기본 스테이지 구성
│  ├─ storage.py           # 진행 상황 저장 및 불러오기
│  └─ timing.py            # 시간 측정 및 별점 계산
├─ scripts/                # 보조 스크립트
├─ tests/                  # 테스트 코드
├─ README.md
├─ requirements.txt
└─ pyproject.toml
```

> **프로젝트 구조 표기 기준**
> 위 구조는 저장소의 모든 파일을 빠짐없이 적은 전체 목록이 아니라, 제출 문서에서 이해가 필요한 **대표 폴더와 핵심 소스 파일 중심의 요약**입니다.
> 실제 저장소에는 이미지/사운드 에셋, 스테이지 데이터, 테스트 파일, 보조 스크립트, GitHub 설정 파일, 개발 도구 설정 파일 등이 더 포함될 수 있습니다. 이러한 파일들은 실행 흐름을 설명하는 데 직접 필요한 핵심 소스가 아니거나, `assets/`, `data/stages/`, `scripts/`, `tests/`, `.github/` 같은 폴더 단위로 묶어 설명하는 편이 더 읽기 쉽기 때문에 세부 파일명을 생략했습니다.
>
> 특히 `assets/`의 개별 이미지·사운드 파일, `tests/`의 세부 테스트 파일, `scripts/`의 보조 자동화 파일은 게임 실행과 품질 관리에 필요하지만, 보고서의 프로젝트 구조 표에서는 전체 구조를 복잡하게 만들 수 있어 폴더 단위로만 정리했습니다. 반대로 `__main__.py`, `game.py`, `models.py`, `resources.py`, `stage_catalog.py`, `storage.py`, `timing.py`처럼 게임 실행 흐름과 직접 연결되는 파일은 주요 파일로 따로 적었습니다.

## 8. 주요 클래스 구조

| 클래스/모듈 | 역할 |
|---|---|
| `Game` | Pygame 초기화, 메인 루프, 이벤트 처리, 화면 전환, 스테이지 진행 관리 |
| `Scene` 계열 | 메인 화면, 스테이지 선택, 게임 진행, 실패, 결과 화면 등 화면별 동작 관리 |
| `Stage` / 모델 계열 | 플레이어 위치, 장애물, 이동 결과, 클리어/실패 조건 등 게임 규칙 관리 |
| `SoundManager` | 효과음과 배경음 로드 및 재생 |
| `ResourceManager` | 이미지 등 리소스 등록 및 조회 |
| `SaveManager` | 진행 상황 저장 및 불러오기 |
| `Timer` | 스테이지 플레이 시간 측정 |
| `StarRating` | 클리어 시간 기반 별점 계산 |

## 9. 과제 요구사항 충족 여부

| 요구사항 | 구현 내용 |
|---|---|
| GUI 윈도우 기반 실행 | Pygame 창을 생성해 게임을 실행 |
| 시작 → 진행 → 종료/결과 화면 전환 | 메인 화면, 스테이지 선택, 게임 진행, 실패, 결과 화면으로 상태 전환 |
| 게임 상태 표시 | 스테이지 진행 상태, 클리어 시간, 별점, 결과 정보 표시 |
| 키보드 이벤트 처리 | Pygame 이벤트 루프에서 키 입력 처리 |
| 사운드 1종 이상 | 이동, 충돌, 환경음, 배경음 등 여러 사운드 사용 |
| 파일 저장/불러오기 | 진행 상황과 스테이지 클리어 정보를 저장 및 불러오기 |
| 사용자 정의 클래스 | `Game`, `SoundManager`, `SaveManager`, `Timer` 등 여러 클래스 사용 |
| 독자적 변형 요소 | 건국대 캠퍼스와 건구스 캐릭터 테마, 스테이지별 기믹, 별점 시스템 적용 |
